budget_app 학습 문서 — 목차와 읽기 가이드

이 폴더는 budget_app(파일 기반 가계부 콘솔 프로그램)의 전체 코드와 설계를 초보부터 고급까지 해설하는 문서 시리즈입니다. 이 프로젝트는 과제 명세에 따라 AI 가 생성한 코드이므로, 코드를 직접 작성하지 않은 사람이 쓰인 문법·기법·설계를 완전히 이해하고 남에게 설명(과제 방어)할 수 있게 만드는 것이 목적입니다.

모든 문서는 실제 소스 코드와 대조·검증되었으며, 코드 인용에는 budget_app/파일.py:라인 형식의 정확한 위치가 함께 표기되어 있습니다.

시리즈는 두 축으로 답합니다. 01~11 은 "이 코드를 왜 이렇게 설계했는가"를, 12번은 "이 관용구가 어디서 왔고(PEP·도입 버전·무엇으로 풀리는가) 라이브러리 안에서 어떻게 도는가"를 다룹니다. 01~11 본문 곳곳의 🔎 문법의 출처 / ⚙️ 내부 동작 상자가 두 축을 잇습니다.

이 시리즈는 네 차례 리팩터를 반영해 재작성되었습니다. ①책임 분리(7→15모듈)와 데이터 무결성 버그 3종 수정 → ②계층별 패키지 재배치 → ③계층별 파일 분할·값 객체·디자인 패턴 도입 → ④코드 리뷰 후속(43파일, 회귀 테스트 136개). 각 문서는 "무엇이 바뀌었고 왜 바꿨는지"를 함께 설명하므로, 리팩터 전후를 대조하며 읽으면 설계 판단의 근거가 가장 잘 드러납니다.

4차 리팩터에서 고친 것(FIX_PLAN.md 기준 6단계): 날짜/월·거래 id 정규화 누락, 삭제된 id 재사용, 카테고리 자기 대체 우회, 찢어진 꼬리 append, 바이트 손상 줄이 파일 전체를 죽이던 문제, CSV BOM, 오류 방패 밖에서 터지던 --data-dir, --limit 0 의 거짓 안내, UnitOfWork 커밋 실패 후처리, 이중 전체 스캔, 엔티티 가변성, 그리고 문서와 코드가 어긋난 주장들. 자세한 내용은 각 문서의 해당 절에 있습니다.

문서 규약

  • 코드 인용은 원문 그대로이며, 코드블록 위의 budget_app/파일.py:시작-끝 표기는 작성 시점의 실제 라인 번호입니다. 이후 소스가 수정되면 라인 번호가 어긋날 수 있습니다.
  • ... 한 줄은 생략 표시입니다. 소스의 docstring 이 길어 코드가 가려지는 자리에서 첫 줄만 남기고 줄였습니다. 생략한 자리를 반드시 ... 로 드러내므로, 생략이 없는 인용은 원문 그대로입니다.
  • 인용 508곳의 파일·라인·본문은 소스와 자동 대조해 검증했습니다.
  • "개선안" 또는 "일반론"으로 표시된 내용은 현재 코드에 없는 내용입니다. 그 외의 서술은 전부 코드에서 확인된 사실입니다.
  • "리팩터 전 — 지금은 없는 코드"로 표시된 블록은 과거 코드입니다. 비교를 위해 인용한 것이며 현재 소스에는 존재하지 않습니다.
  • 난이도: 🟢 초보(파이썬 기본 문법만 알면 됨) / 🟡 중급(02·03 문서의 기법 이해 필요) / 🔴 고급(설계 트레이드오프 논의) / 📘 사전(순서대로 읽지 않고 찾아보는 문서).
  • 🔎 문법의 출처 상자는 "이 표기가 어느 PEP·어느 파이썬 버전에서 왔고 그 전에는 무엇으로 썼는가", ⚙️ 내부 동작 상자는 "이 호출이 CPython 안에서 실제로 무슨 일을 하는가"입니다. 둘 다 12번 문서의 해당 절로 연결됩니다.
  • PEP 번호와 도입 버전은 표준 라이브러리 소스와 실행으로 대조해 검증했습니다. 다만 "실행하면 이렇게 나온다"고 적힌 출력은 CPython 3.13.1(Windows) 관측이고, "이 버전에 도입되었다"는 서술과는 별개입니다. 이 프로젝트가 요구하는 것은 3.10 이상입니다.

이 도면집을 읽는 법

색은 계층을 뜻하고 27장 전체에서 같은 뜻을 유지한다. 한 번만 외우면 어느 장이든 읽힌다.

domain — 규칙·모양 storage — 파일 I/O services — 정책 cli — 표현 root — 계층 밖 파일 · 디스크 오류 · 중단 정상 종료
  • 도면 시트는 두 테마에서 모두 종이색을 유지한다 — 인쇄된 도면을 제도판 위에 올려 둔 것으로 보면 된다.
  • 처음에는 폭에 맞춰 도면 전체가 한눈에 들어오도록 축소돼 있다. 글자가 작으면 ⛶ 로 전체 화면을 켠 뒤 필요한 곳만 확대하면 된다 — 벡터라 몇 배를 키워도 선이 뭉개지지 않는다.
  • 시트 오른쪽 위에서 그 도면만 조작한다 — − 축소, 가운데 배율을 누르면 맞춤으로 복귀, + 확대, ⛶ 전체 화면(Esc 로 닫기). Ctrl+휠로도 확대된다.
  • 확대해서 도면이 시트 밖으로 넘치면 마우스로 끌어 옮길 수 있다. 커서가 손 모양이 되는 것이 "지금 끌 수 있다"는 신호다 — 맞춤 배율에서는 넘치는 부분이 없으므로 손 모양이 되지 않는다.
  • 제목 아래 회색 경로 는 그 도면이 그린 실제 소스 파일이다.

왜 Mermaid 인가

요구가 생략 없음 과 확대·축소에 안 깨짐 이었다. 이 둘은 서로 당긴다 — 전부 한 장에 담으면 읽을 수 없고, 읽히게 만들면 뭔가를 빼야 한다. 해법은 벡터 + 분할이다. Mermaid 는 텍스트에서 SVG 를 만들므로 배율 손실이 없고, 소스가 코드라 git 에 들어가며 코드가 바뀌면 diff 로 보인다. PNG 나 화면 캡처는 두 조건 모두에서 진다.

27장으로 나눈 것은 타협이 아니라 도면집의 표준 관행이다. 건축 도면도 한 장에 전부 그리지 않는다 — 배치도·평면도·상세도가 각각 있고 색인이 그것을 하나로 묶는다. 여기서는 색인이 좌측 레일이고, 색이 계층을 27장 내내 같은 뜻으로 유지한다.

소스를 뽑아 다시 그리려면

이 페이지의 각 도면은 pre class="mermaid" 블록 안의 순수 텍스트다. 브라우저에서 Ctrl+U 로 소스를 열거나 원본 HTML 에서 블록만 뽑아 .mmd 파일로 저장하면 아래 도구 어디서든 열린다.

자동 생성 도구는 대조용이지 대체용이 아니다. pyreverse 는 클래스와 상속을 정확히 뽑아내지만 "왜 frozen 인가", "왜 워터마크와 파일 스캔을 둘 다 보는가" 같은 결정의 이유는 코드에 형태로 남지 않는다. 각 시트에 붙은 설명 문단이 그 부분이고 그건 사람이 써야 한다. 반대로 손으로 그린 도면은 코드가 바뀌면 조용히 낡으므로, 자동 생성물과 정기적으로 대조하는 편이 좋다.

  • pyproject.toml 이 런타임 의존성 0 을 지키고 있다. 위 도구는 전부 uvx 나 npx 로 일회 실행하고 dependencies 에 넣지 않는 편이 그 약속을 지킨다.
  • 도면과 코드가 어긋나기 시작하면 가장 먼저 낡는 것은 도면 09(명령 대응) 와 도면 26(설정 소유권) 이다. 명령이나 상수를 추가할 때 이 둘을 같이 고치면 나머지는 오래 버틴다.
  • 도면 02 의 화살표는 tests/test_architecture.py 가 이미 강제하고 있다 — 그 테스트가 통과하는 한 도면 02 는 틀릴 수 없다. 도면을 테스트로 묶는 이 방식이 다른 장에도 쓸 수 있는 가장 값싼 유지 수단이다.
